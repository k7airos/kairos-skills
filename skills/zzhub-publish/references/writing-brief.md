# 写稿 Brief 构建指南

当 `next_action.action` 为 `attach-body` 且需要生产正文时，按用户需求构建写作 Brief。已有完整正文直接挂载，不再生成一篇。允许且具备委派能力时可交给子代理，否则主 Agent 按相同要求完成。

## 工作模式

从 `next_action.params.worker_mode` 读取：

- **write**：从零写一篇新文章。任务中的 `intent_text` 描述了用户想要的内容。
- **write-from-materials**：`source_materials_path` 有上游素材。先读完再写。
- **research-then-write** / **research-then-write-from-materials**：先调研再写稿。用网络搜索收集事实信息，然后动笔。

## 构建写作 Brief

主 Agent 根据 `intent_text`、`worker_mode` 和用户原始需求构建写作 Brief，包含：

- 文章主题、目标读者、字数要求
- 需要覆盖的核心要点和角度
- 语气和风格要求（见下方质量要求）
- Markdown 格式规范（见下方格式要求）
- **标题要求**：用户已有标题时保留；需要拟题时准确概括内容，文风服从任务，不把点击率要求套到新闻、操作说明等所有文章。
- **标题关键词**：需要文字封面时，可从标题中另选 1-2 个实际出现的词，作为封面参数单独返回，不属于正文。

## Spawn Sub-agent

使用当前环境提供且允许的委派工具，prompt 中只包含 Brief、必要素材和格式规范，不夹带无关主对话或状态机细节。没有委派工具时直接写作，不将工具名称或子代理类型写成前置依赖。

## 交稿流程

写作结果将正文、标题和可选封面词分开。主 Agent 检查事实与语法，将纯正文保存到文件后交稿；若旧稿末尾有 `**封面高亮关键词**: ...`，提取并移除该行，避免发进文章：

```bash
zzp attach-body --state "{state_path}" --body "{body_md}"
zzp status --state "{state_path}" --view agent
```

优先文件输入，避免正文中的引号、反引号或 `$()` 被 shell 解释。临时文件使用当前任务独占目录。

当下一步为 `prepare` 且已有明确标题/封面词时，可传入：

```bash
zzp prepare --state "{state_path}" --title "{title}" --highlight-words "{word1},{word2}"
```

未传封面词时由 `prepare-finalize` 从标题提取。Studio 模板是否显示高亮取决于模板；不要保证所有模板都呈现相同效果。

## 写稿格式与排版组件要求

按 [milkdown-writing](../../milkdown-writing/SKILL.md) 核对本次使用的语法，组件按需选择：

- **标题层次**：正文需要章节时用 `## 章节名`，章节之间留空行。文件首行可用 `# 标题` 供元数据提取，finalize 会移除开头的标题，避免正文重复。
- **篇章导读与文末互动（核心组件）**：
  - 开篇需要导读时，使用 `> [!INTRO] 导读`，概括文章核心问题与阅读预期；
  - 结尾需要互动、交流或引导时，使用 `> [!CTA] 互动交流`；
  - **关键语法点**：卡片内每行都必须带 `>`，多段之间用单独的 `>` 空行分隔；卡片外部用普通空行隔离。
- **提示块与重点强调**：
  - 提示块使用 `> [!NOTE] 标题`、`> [!TIP] 建议`、`> [!WARNING] 注意` 等；
  - 核心论断或金句使用 `==关键结论==` 高亮标注；
  - 操作快捷键使用 `[[kbd:Cmd]] + [[kbd:K]]`；
  - 标签与属性使用 `[badge:brand|推荐]`（支持 brand、success、warning、danger、info）；
- **常规排版**：按需用 `**粗体**` 强调关键数据，段落长度服从内容与移动端阅读，不规定统一句数。
- **边界防错**：不要手写 HTML/CSS 模拟卡片；公式、Mermaid、文内锚点在微信导出中不支持，勿作为排版组件使用。

## 写稿质量要求

首先遵守用户文风；下列个人叙事与传播技巧仅在相应用途下参考，不作为每篇文章的硬性验收标准。不得为制造场景、冲突或精确数字编造经历和事实。

### 一、标题（需要拟题时）

- 按文章用途选择标题，准确性优先；面向个人传播时可参考：
  - **悬念**：让人产生"这说的是什么？"的好奇心（例：《停止继续探索 OpenClaw，回到打磨 SKILL 上来》）
  - **冲突**：有对立面或张力（例：《稳定是最大的牢笼》）
  - **反差**：打破常识预期（例：《30 岁前端开发离失业还有几年》）
  - **具体数字**：精确数据比模糊描述更抓人（例：《一个月内写了 16w+ 行代码》）
- 传播型标题避免空泛或过度宣传；说明性标题可直接陈述。

### 二、风格（作者个人特征）

- **开头**：一个具体场景或精确数据直接切入，不铺垫。例：《从大学毕业到现在，已经第九年了》《周六回了老家》。
- **叙事**：场景还原能力强——对话直接引语、动作细节、感官描写。然后从具体突然跳到抽象感慨。
- **语言**：口语化自言自语（"还挺高级嘞""没糖那个是真难喝"）；括号补充内心 OS（"(放心吧老板,已经给您备注好了)"）；技术词保持英文不翻译（OpenClaw、Skill、Agent、Token）；数据精确到小数点（288.66 元、47844 行代码）。
- **结构**：一篇里生活/技术/情绪自然混写，不割裂；可以突然转弯从具体跳到抽象。
- **价值观**：直给不绕，对割韭菜等行为不藏着批评。
- **结尾**：自然停下，不追求"总结三点"式收尾，偶尔一句感慨收束但不升华。

### 三、写作手法（借鉴名家技巧）

- **余华式细节**：用克制、冷静的笔触写日常场景，让情感从细节里自然渗出来，不直接煽情。例：写亲情不是"我很感动"，而是"他摆了摆手，冲我嘿嘿一笑，风一样的速度就骑走了"。
- **刘震云式绕**：把一个道理用反复、递进、自我否定的方式说出来，形成节奏感。例："你以为的 A 其实是 B，而 B 背后还有一个 C。"
- **场景切片**：不写"我这一周很累"，写"孩子偷喝柠檬水、姥爷骑车、帐篷里躺着"——用 3 个具体场景让读者自己感受到累。
- **突然转弯**：叙事进行到一半突然跳到抽象思考，制造认知冲击。例：从孩子偷喝饮料 → "生孩子好不好这种问题让中年人像走马灯"。

### 四、互联网传播（流量特征）

- **开头**：尽早交代具体问题、场景或数据。
- **段落衔接**：按内容自然推进，不为了悬念在每段末尾添加反问或转折。
- **冲突前置**：有争议、有对立面、有张力。不是平铺直叙"我做了什么"，而是"我做了什么 vs 常规认知是什么"。
- **反差制造记忆点**：打破读者预期。例：以为在写技术 → 突然聊到人生；以为在聊日常 → 突然给出深刻洞察。
- **重点表达**：有可核验的结论时清楚表达，不按固定字数制造金句。
- **情绪曲线**：不要平铺直叙。要有起伏——平静 → 冲击 → 反思 → 释然（或反转）。

### 五、封面高亮关键词（联动 typeset-studio / imgx）

- 需要时在交稿元信息中单独返回，不放入 Markdown 正文文件。
- 这些关键词必须来自标题中实际出现的词，选 1-2 个最有冲击力的词。
- **作用**：提供给渲染器作为封面高亮输入，具体呈现取决于模板，不改变正文样式。

### 六、禁用清单（AI 腔黑名单）

修订空话与重复表达，保留必要的原话引用；以下是常见检查项：
- 开头禁用："在当今数字化时代…""随着 AI 技术的快速发展…""近年来…"
- 过渡禁用："让我们一起来看看""接下来我们来看看""下面我们来聊聊"
- 结尾禁用："让我们一起期待…""未来已来""让我们拭目以待"
- 套话禁用："值得一提的是""需要注意的是""总而言之""综上所述"
- 形容词禁用："令人惊叹的""不可思议的""颠覆性的""革命性的"
- **句式检查**：避免反复使用"不是xxxx，而是xxxxx"制造空泛对比。

### 七、新闻类文章硬性约束

当文章内容属于**新闻报道类**（AIHOT新闻、行业动态、产品发布报道等）时，额外强制以下规则：

1. **风格严谨克制**：新闻稿必须以客观事实为主，语气专业、信息准确，不可像普通文章那样随意发挥、碎碎念、情绪化表达
2. **事实优先**：评论是否允许取决于用户要求；自动资讯流程只陈述来源支持的事实。允许评论时也应清楚区分，不用固定比例替代事实核验。
3. **数据支撑**：观点必须有对应的数据、来源或事实依据支撑，不能空口说"很强""很好"
4. **信息来源标注**：关键事实应标注来源（如"据智谱官网介绍""根据 Artificial Analysis 榜单数据"），增强可信度

**普通文章不受此约束**——只有新闻类内容需要额外遵守这些规则。
