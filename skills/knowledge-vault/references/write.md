# 简单更新与候选审核

## 授权

`write_policy` 决定能否写入：

- `read-only`：只读。
- `explicit`：当前任务或已有明确持续授权覆盖相应写入时执行；否则请求授权。
- `auto-draft`：本 Skill 因持久知识任务触发后，可记录本次相关耐久事实；不是每次普通编码结束的全局 Hook。

`promotion_policy` 决定候选如何晋升为正式知识：

- `explicit`：候选晋升需要用户明确授权。
- `auto-verified`：来源稳定、目标唯一、无实质冲突时允许自动晋升——搭配 `auto-draft` 意味着已核验的事实可直接更新正式页而无需先进 Inbox。

纯查询始终只读。TODO 更新也遵守 write_policy，不能借“交接”绕过库的授权。

## 选择最小路径

| 内容 | 放哪里 | 是否需要候选 |
| --- | --- | --- |
| 已有页的小修、已确认决定、稳定提交支持的事实 | 唯一正式页，附来源 | auto-verified 下不需要；explicit 按授权 |
| 新的稳定知识且目标唯一、来源明确、无冲突 | 新建或合并正式页 | 同上，不强制先进 Inbox |
| 未提交实现、来源不稳、事实冲突、权限或归属不清 | Inbox，必要时在 TODO 引用 | 需要；写清阻塞，不标 verified |
| 任务进度、已做/未做、下一步和恢复线索 | TODO / handoff | 不要求晋升；见 tasks.md |
| 临时调试、重复知识、纯格式改动和聊天流水 | 不记录 | 不需要 |

不要为一个主题同时维护候选、正式正文和交接正文三份真相源。交接只记录进度与定位，正式页记录稳定结论，候选只记录待解决事实。

## 来源与状态

- 代码事实引用仓库标识、稳定 commit 和路径/符号；个人绝对路径留在所选私有库或本机映射，公共 Skill 示例仅用占位符。
- 本地来源记录路径与内容哈希；网页记录URL与采集日；用户确认用 `user-confirmed:<日期>:<会话或上下文>`。
- 当前事实写核验范围；用户决定写来源；规划标“待实施”；运行观察标日期。新证据明确取代旧决定时更新当前页，旧来源留历史/日志；无法解释的冲突才阻塞。
- 修改页更新 `updated`；仅对重新核验的范围更新 `verified`，不要因改一段就刷新整页核验日期。只有已核验的事实/决定可标 verified；规划仍明确标为未实现。

## 一次变更的闭环

1. 按目标、别名与主题搜索已有知识和活跃候选；只读取需改文件并记录读取时内容。
2. 写入前复核待改文件是否仍与读取时一致；有并发变化则重读合并，无法可靠合并时停止该文件，不覆盖他人工作。多文件补丁不是数据库事务，不承诺不存在竞争窗口。
3. 更新相关正式页或候选；仅路由/摘要变化才改 INDEX。一次操作追加一条简短 log，必要时更新 TODO。不要每个段落建立一份候选或日志。
4. 回读变更页并核对相关链接/来源。多文件未完成时报告实际状态，不能声称已完整晋升。
5. 按 [git.md](git.md) 完成库自己的提交/同步规则。

## 需要候选时

同 `target + topic` 只维护一个活跃候选，已有则补证据；多个活跃候选确认同主题后归并，保留 merged 记录。新文件用 `inbox/<target>--<topic>--<时间戳>-<短随机值>.md`，不得覆盖已有文件。

```yaml
candidate_id: <唯一ID>
target: <vault-id>.<实体ID>
topic: <稳定主题>
status: blocked
updated: <日期>
sources: [<可定位来源>]
promotion_blockers: [<缺失证据或冲突>]
```

正文只需观察、建议变更和未知项。`pending` 表示尚待本轮审核，`blocked` 表示证据或授权未满足，`merged` 表示已归并并写明 `merged_into`。auto-verified 候选有新证据后同轮审核：来源稳定、目标唯一、无实质冲突、未越界且无秘密时晋升，否则说明 blocker；不让无事可做的候选无限停在 pending。

维护 Inbox 仅在用户要求或已授权调度时运行。先读元数据，每次最多处理10条相关 pending；没有新证据不反复重读 blocked，也不把 todo 的“计划”当成缺失证据已经解决。

## 修改 Skill 自身

纯查询和普通维护不得自改 Skill。用户授权改进时，直接在唯一源码仓修改、说明真实触发问题、做针对性校验并提交，不为已授权修订额外绕一轮元候选审批。未授权的建议只报告；组织隔离或权限策略的变更不能借自更新扩大授权。公共 Skill 不包含库内内容、真实路径或秘密。
