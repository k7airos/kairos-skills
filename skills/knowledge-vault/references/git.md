# Git 与同步

Git策略属于每个Vault，不在Skill中指定GitHub账号、仓库名或自动推送目标。先读根目录AGENTS.md与KNOWLEDGE.md；若无Git约定，不擅自初始化、创建远端或推送。

## 已授权版本管理的库

1. 编辑前检查 `git status --short`、当前分支和远端；记录原有改动，保留其他会话工作。需拉取时，只有工作区干净且不改变用户在途工作才用 `git pull --ff-only`，发生分叉/冲突不强制覆盖。
2. 完成相关知识、TODO、来源、必要索引与日志更新后，检查diff；提交路径应明确，禁止 `git add .` 混入未知改动。提交前检查已有暂存区，不提交他人的暂存内容。
3. 只同步内容与必要维护规则。整个 `.obsidian/`、社区插件配置、workspace、缓存、回收站、临时文件、日志和密钥文件排除；`.gitignore`不能移除已跟踪文件，发现时按用户授权有针对性取消跟踪，保留本地文件。
4. 根据库规则创建一次有意义的commit；无需每次写文件都commit，不制造空commit，不amend其他提交。
5. 仅向库已批准的remote/branch推送；失败保留本地commit并报告原因，不强推、不临时改成公共仓库、不自动换远端。核验远端提交后再称“已同步”。

私有Git仓库也不能放密钥或跨库内容。源码版本不能替代用户数据、外部存储或凭据恢复备份。公共Skill的Git与私有Vault的Git是两个边界，分别提交，不打包上传知识库到Skill源码仓。
