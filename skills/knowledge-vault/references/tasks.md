# TODO、渐进沉淀与交接

## 分工

- `TODO.md`：当前工作索引，维护状态、下一步和相关知识/证据链接；不是正式事实库或无限期想法清单。
- `handoffs/<task-id>.md`：复杂或中断任务才需要的恢复说明；简单任务直接写在TODO，不强制多建文件。
- `knowledge/`：已稳定且可复用的事实、规则和决定。一个阶段稳定就可沉淀，不等整个项目结束。
- `inbox/`：暂不能核验或解决冲突的知识候选。未完成任务本身不等于知识候选。

沿用已有任务系统和状态，不另建第二份任务真相源。外部issue/看板/流水线已权威管理状态时，TODO只放链接和续接所需摘要。写TODO不授权执行其中的开发、部署、发送或发布；必须依赖当前用户任务授权。

## 最小条目

```markdown
- [ ] <ID> <任务名> — 状态：doing / next / blocked；更新：<日期>
  - 已完成：<能定位的结果与验证边界>
  - 下一步：<一个具体动作>
  - 入口：<仓库/分支、相关知识、issue或可选handoff>
```

任务ID稳定，现有条目就地更新，避免每次会话新建“同一个任务”。没有明确期限不编造deadline；blocked写明原因/解除条件；完成用 `[x]`、记录结果来源，必要时归档到已有历史区，不抹去交接证据。

## 交接内容与恢复

复杂handoff只写目标/范围、已确认决定、当前进度、仓库和分支/commit、相关未提交文件、已经做过与未做过的验证、下一步与阻塞。含工作区信息时记采集时间；它是当时快照，不是最新运行态。禁止粘贴正文全量、凭据、长命令日志或整个聊天。

续接先读TODO指定条目与handoff，再核验仓库状态、相关commit和外部任务状态；不能仅凭旧handoff断言进程还活着、改动已合并或部署已完成。只读加载与执行授权分开。

每次有意义的阶段结束或任务中断，按库write_policy更新已授权条目；没有新进度不制造日志/commit。稳定部分更新正式页并链接，尚未完成的内容保留任务里，未提交但值得保留的事实只以在途证据记录或进入候选。

## 周期回顾

仅由用户授权的调度触发；调度配置在Vault外，不内置特定Agent/云平台。默认先看TODO、INDEX、最近日志和变更，必要时查对应项目，不全盘扫描或重读所有blocked。

回顾关注：任务是否失去下一步、交接是否过时、已完成阶段是否未沉淀、资产是否仍活跃、部署/备份证据是否需更新。每次汇总少量最有价值的行动；不擅自执行发布、删除或跨库访问。通知频率按用户偏好，不把“定期”理解成每次无变化也发状态。
