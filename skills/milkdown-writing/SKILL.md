# Milkdown 写作语法

让 Agent 写出的 Markdown 能被 myno、Pipeline 和复用它们的宿主正确解析。支持范围以实际接入的解析器和微信导出链路为准，不能把 Milkdown 的可选插件都当成已支持。

## 写作时

- 先遵守用户给出的内容、作者、账号和写作风格；语法清单表示可用能力，不要求每篇文章全部使用。
- 查阅 [语法与导出规则](references/syntax.md) 中本次涉及的部分。保持文章含义、事实和不确定程度；只做语法整理时不要顺带重写内容。
- 用 Markdown 表达结构，让账号主题决定颜色、间距和卡片外观。不要手写 HTML/CSS 模拟组件。
- 默认交付 Markdown 正文，不把全文包进代码围栏；用户要语法示例时才展示源码块。

## 导读与文末卡片

文章开头需要导读时，用 `[!INTRO]` 概括文章要回答的问题和内容范围；文末需要交流、关注或引流时，用 `[!CTA]`。两者按文章用途选用，避免重复催关注。

```markdown
> [!INTRO] 导读
> 本文介绍导读和文末卡片的写法，并说明多段内容如何保持在同一卡片中。

## 正文标题

正文内容。

> [!CTA] 交流与反馈
> 你在排版时遇到过什么问题？欢迎留言交流。
```

- 标识放在引用块第一行，标题写在同一行，使用普通文本。卡片至少保留一段正文。
- 卡片内每行都写 `>`；段落之间用单独的 `>` 空行。卡片外用正常空行分隔。
- 导读可添加已确认的作者、预计阅读时间和关注引导，见参考文档。不要照抄示例作者、时长或账号。
- 引流卡片只使用用户提供或确认过的账号、链接、二维码和领取方式；未知时用相关的交流邀请，或省略引流。语法不会自动创建二维码、下载入口或自动回复能力。

## 自定义语法速查

| 用途 | 写法 |
| --- | --- |
| 导读 / 文末互动 | `> [!INTRO] 标题` / `> [!CTA] 标题`，下一行写引用正文 |
| 提示块 | `> [!NOTE] 标题`；另有 `TIP`、`IMPORTANT`、`WARNING`、`CAUTION` |
| 高亮 | `==关键结论==` |
| 快捷键 | `[[kbd:Cmd]] + [[kbd:K]]` |
| 徽章 | `[badge:brand\|推荐]`；另有 `success`、`warning`、`danger`、`info` |

徽章和快捷键放在普通段落、列表正文或标题的直接文本中，避免嵌进加粗、链接或表格。图片可见图注写在 `title`，如 `![替代说明](图片地址 "可见图注")`。

## 交付前检查

检查卡片是否被无 `>` 的空行截断，标识及徽章类型是否有效，图片和引流地址是否来自真实资料。微信导出会自动整理外链引用，不承诺保留外链点击、交互任务框或文内锚点跳转。公式、Mermaid、脚注、折叠块等未接入能力不要当成可发布组件。

普通写作无需启动服务或试发草稿。用户要求验证导出时，再使用现有导出流程；本 skill 不授权发布、上传或部署。

## 样式与执行的分工

Markdown 语法与排版配置分开维护。myno 可独立调样式、复制富文本并导出 `wechat-style.json`，不需要 Pipeline 或公众号凭据；Pipeline 通过可选 myno 插件读取同类配置，也保留内置排版器。Typeset Studio 负责封面与贴图 PNG，不改变正文语法。

用户要求切换插件、选择独立 JSON 或同步配置时，查阅 [排版接入参考](../zzhub-publish/references/rendering.md)；需要执行发布任务再用 [zzhub-publish](../zzhub-publish/SKILL.md)。只写文章时不要自动保存账号主题、上传素材或改全局配置。

## 维护此 skill

自定义语法变更后，根据 [维护依据与刷新流程](references/syntax.md#维护依据与刷新流程) 更新同一份参考文档及必要示例。记录验证日期和实际安装版本，核对注册项、解析实现与导出行为；不要仅凭包 README 或尚未安装的源码宣称已支持。共享 skill 保持单一来源，Agent 目录用软链接引用。
