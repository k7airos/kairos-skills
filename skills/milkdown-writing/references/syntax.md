# 当前 Milkdown 语法与微信导出规则

验证日期：2026-10-13。当前 Pipeline 导出链路使用 `commonmark + gfm + getCombinedMilkdownPlugins()`；自定义包为 `@akairos/milkdown-article-plugins@0.1.3`，共享样式为 `@akairos/milkdown-article-style@0.1.1`。以下是这条链路的写作能力，不代表所有 Milkdown 宿主都安装了相同功能。

按需查阅：基础 Markdown、篇章卡片、提示块、行内扩展、图片、微信导出边界、维护依据。基础语法可用不等于文章必须采用列表等结构；配合作者已有的写作风格使用。

## 基础 Markdown

| 结构 | 支持写法与注意点 |
| --- | --- |
| 标题 | `#` 至 `######`；也支持下一行用 `===` / `---` 的 Setext 标题。通常用二、三级标题组织正文，避免层级过深。 |
| 段落 | 空行分段；单个源码换行是软换行，不保证视觉换行。行末 `\` 或两个空格可产生硬换行。 |
| 强调 | `**加粗**` / `__加粗__`、`*斜体*` / `_斜体_`、`~~删除线~~`；可合理组合。 |
| 行内代码 | 单反引号包围；内容含反引号时用更多反引号作定界符。代码内自定义语法保持字面文本。 |
| 代码块 | 三个或更多反引号 / 波浪线围栏，可指定语言；也支持四空格缩进代码块。不要承诺执行或交互。 |
| 列表 | `-`、`*`、`+` 无序列表；`1.` 或 `1)` 有序列表；按父项缩进嵌套。列表内多段内容也要保持缩进。 |
| 任务列表 | `- [ ] 待办`、`- [x] 完成`；微信导出为静态勾选标记。 |
| 引用 | 行首 `>`，支持多段与嵌套引用；多段引用的空行也写 `>`。 |
| 表格 | GFM 管道表格，至少有表头和分隔行；`:---` / `:---:` / `---:` 控制对齐，单元格内的竖线写 `\|`。避免复杂多段、合并单元格或宽表。 |
| 分隔线 | 独立行 `---`、`***`、`___`；前后留空行，避免被解析成 Setext 标题。 |
| 链接 | `[文字](https://example.com "可选标题")`，也支持完整、折叠与简写引用式链接。使用真实目标地址。 |
| 自动链接 | `<https://example.com>`、`<reader@example.com>`，GFM 也识别合规的裸 URL / 邮箱。正式文章优先使用说明清楚的链接文字。 |
| 图片 | 内联式与引用式图片；独立段落图片支持可见图注，详见图片部分。 |
| 转义与实体 | `\*字面星号\*`、`\[普通括号\]`，以及 `&amp;`、`&copy;`、`&#x4e2d;`。 |

表格示例：

```markdown
| 配置 | 含义 | 数量 |
| :--- | :---: | ---: |
| **模板** | 封面布局 | 2 |
| 转义竖线 \| | 正文字符 | 1 |
```

代码块示例（外围四反引号只用于在本文展示源码）：

````markdown
```typescript
const title = "排版示例";
```
````

YAML frontmatter 是 Pipeline 单独处理的文章元数据，导出前会移除，不是正文排版组件。是否填写 `title` / `slug` 等字段以当前工作流要求为准，勿为了套模板自行增加配置。

## 篇章卡片：导读与文末引流

### 标识与结构

| 推荐标识 | 兼容别名 | 用途 |
| --- | --- | --- |
| `[!INTRO]` | `[!PREFACE]` | 开篇导读、作者与阅读元信息、可选关注引导 |
| `[!CTA]` | `[!OUTRO]` | 文末交流、关注或用户明确要求的引流 |

标识大小写不敏感，写作统一使用推荐的大写标识。第一行可省略标题，届时导出使用默认标签「导读 · READING GUIDE」或「互动交流 · CONNECT」，自带图标。

标识必须位于引用块首段的开头，不要在前面加正文、表情或加粗符号。标题写在同一行，用空格与标识分开，标题内避免 Markdown 格式。下一行起写正文；只有标识、没有内容的空卡片不用于文章。

多段导读示例（作者、时长、账号是占位内容，使用时替换为已确认信息，未知项整段删除）：

```markdown
> [!INTRO] 导读
> **文 / 已确认的作者** · 预计阅读约 N 分钟
>
> 用一小段交代文章要解决的问题、讨论范围，以及读者看完能理解什么。
>
> 欢迎关注公众号「已确认的账号名」。
```

段落间单独的 `>` 很重要：作者信息、导读正文、关注引导各占一段，才能分别识别和排版。没有 `>` 的空行会结束当前引用块。

导读元信息段可识别的开头包括 `文 /`、`文：`、`作者：`、`By `、`执笔：`、`策划：`、`编辑：`、`预计阅读`、`阅读需`、`字数：`、`共 N 字`。预计阅读时间应根据文章合理估计，标明估计，不要沿用示例中的固定数值。

导读段落中出现 `欢迎关注`、`关注公众号`、`星标`、`不错过`、`点击右下角`、`扫码关注`、`关注我们`、`回复「` 等文字，会被识别为关注引导段。只在确有关注引导意图时使用；普通导读正文避免无意触发。

### 文末引流的使用

不需要引流资料也能写交流卡片：

```markdown
> [!CTA] 交流与反馈
> 你在排版时遇到过什么问题？欢迎留言交流。
```

用户提供了账号、资料地址或二维码后，可在同一卡片中放入相应文字、正常 Markdown 链接或图片。图片单独成段，段落间仍写 `>`。外部链接仍遵循微信导出规则，不承诺点击直达；二维码必须使用用户提供的实际图片。

不要自行编造「回复关键词领取」「扫描下方二维码」或下载链接；卡片语法只负责排版，不会生成自动回复、二维码或资料分发服务。文章开头已有关注引导时，文末避免重复同一句话。

## 提示块 Callout

只支持以下五种类型，大小写不敏感。标题可选，支持用开头 Emoji 覆盖图标。

| 类型 | 建议用途 |
| --- | --- |
| `NOTE` | 补充说明、背景、备忘 |
| `TIP` | 可操作的建议与技巧 |
| `IMPORTANT` | 关键前提、必须注意的结论 |
| `WARNING` | 可能发生的问题或操作风险 |
| `CAUTION` | 高代价、不可逆操作或数据风险 |

```markdown
> [!TIP] 实用技巧
> 卡片里有多段内容时，用带引用标记的空行分段。
>
> 第二段仍然属于这张卡片。

> [!WARNING] ⚠️ 操作提醒
> 替换正式配置之前，确认已经保留可恢复的备份。
```

首行与多段规则同篇章卡片。省略标题时使用预设标题和图标；账号配置可能覆盖预设，不要把颜色或图标写死在文案里。

不支持把 `[!INFO]`、`[!SUCCESS]`、`[!DANGER]`、`[!QUOTE]` 当成提示组件，也不支持 Obsidian 的 `[!NOTE]+` / `[!NOTE]-` 折叠后缀或 `:::tip` 指令。避免复杂的卡片互相嵌套。

## 行内扩展

### 高亮

```markdown
这里支持 ==重要结论==、**加粗里的 ==重点==**，以及 ==带 *强调* 的重点==。
```

用 `==...==` 标记短语和关键结论，可用于段落、列表、引用和表格等普通行内内容。不要跨段落，也没有用语法指定颜色的能力。少量使用，避免整段荧光笔。

转义 `\=\=字面等号\=\=` 可保留字面文本；行内代码和围栏代码中的 `==...==` 不会变成高亮。

### 快捷键

```markdown
按下 [[kbd:Cmd]] + [[kbd:K]] 打开命令面板。
```

`kbd` 必须小写，每个按键用一个标记，连接符写在外面。只写实际操作的快捷键。它不是 Obsidian 双链语法。

### 徽章

```markdown
重点内容：[badge:brand|推荐]。
状态示例：[badge:success|已完成] [badge:warning|待确认] [badge:danger|有风险] [badge:info|说明]。
```

仅支持 `brand`、`success`、`warning`、`danger`、`info`，大小写不敏感。`primary`、`purple` 不是当前有效类型，即使旧文档中有此类示例也不要采用。

文字不能为空，内部使用纯文本，不含 `]` 或 Markdown 格式。徽章表示真实状态，不把待确认事项写成「已完成」。

快捷键和徽章的当前转换器只处理段落、列表正文和标题中的直接文本。不要将标记包在 `**...**`、`*...*`、链接或表格单元格中期待组件生效；需要这些上下文时改用普通文字。代码中的写法只会显示源码。

## 图片与图注

独立图片的可见图注来自 `title`，不是 `alt`：

```markdown
![排版结果的替代说明](https://example.com/layout.png "图注：导读卡片与正文之间保持适当留白")

![排版示意][layout-image]

[layout-image]: https://example.com/layout.png "引用式图片的图注"
```

示例域名用于解释语法，正式文章必须替换为真实地址。独立图片段落才能生成图注；混在一句话中的图片不保证有独立图注。

编辑器可能将缩放比例保存在特殊 `alt` 中，如 `![0.50](图片地址 "图注")`。当前导出识别正数、两位小数比例，并读取图片原始尺寸处理缩放；加载失败会报错。通常保留编辑器生成的比例即可，Agent 写作优先使用描述性的 `alt`，不要臆造 `=300x200`、`{width=50%}` 等缩放语法。

本地 CLI 可按 Markdown 文件位置解析相对图片路径；云 Worker 无法访问本机 `/Users/...`。面向远程发布优先使用可访问的 HTTPS 图片，不凭空补图片地址。Typeset 封面模板与正文图片、`[!INTRO]` 卡片分别处理，写导读不会设置封面。账号若已配置自动顶部图片或文末说明，避免在正文重复插入。

## 微信导出边界

- 外部 HTTP(S) 链接转换为文字和 `[n]` 编号，末尾自动追加「相关链接」。重复 URL 会合并，规范化时忽略 fragment 等差异；不用自行再编一套编号。文末 CTA 后可能还有自动相关链接和账号页脚。
- 相对链接、锚点和邮箱不等于已验证的微信导航；不承诺文内锚点跳转或邮箱点击效果。
- 任务框静态展示；代码只展示文本；编辑器中的按钮、拖拽和交互不会变成微信文章交互。
- 标题、分隔线、高亮等会转换为微信安全标签并内联样式，具体外观服从账号主题与 CSS。`pillar`、`magazine`、`mac-style` 等预设名属于配置，不是 Markdown 语法。
- 原始 HTML 会经过清理，脚本、iframe、SVG、公式标签、表单、音视频等危险或不兼容节点会被移除。不要手写 HTML/CSS 布局或把它当成绕过组件限制的方法。

当前发布链路未接入以下能力：LaTeX / KaTeX（`$...$` / `$$...$$`）、Mermaid 绘图、脚注 `[^1]`、自动目录 `[TOC]`、容器指令 `:::...`、Obsidian 双链与嵌入、折叠块、自定义 Emoji 短码。若作为代码示例展示，可放代码围栏；若要作为真实组件使用，需先确认目标宿主的解析与导出均已接入。其他宿主可能另有可选插件，不能据此推定 Pipeline 支持。

## 维护依据与刷新流程

本机已验证入口：

- `zzhub-pipeline` 源码中 `src/wechat-preview/browser/editor-export.ts`：实际解析组合。
- `zzhub-pipeline` 源码中 `src/wechat-preview/browser/studio/studio.ts`：排版 Studio 使用的解析组合。
- Pipeline 安装的 `node_modules/@akairos/milkdown-article-plugins/dist/registry.js` 与 `builtin-*.js`：生效的插件注册与解析实现。
- `milkdown-article-plugins` 源码中 `src/`：自定义插件开发源码；必须核对已安装版本，源码改动不等于宿主已经生效。
- `zzhub-pipeline` 源码中 `src/wechat-preview/wechat-renderer.ts`：图片图注、缩放、外链、静态任务框和微信安全输出。
- `zzhub-pipeline` 源码中 `src/wechat-preview/fixtures/all-nodes.md`：节点验收稿，含清理危险 HTML 的测试内容，不能直接作为写作模板。

维护时在实际消费插件的项目根目录查询已安装注册表：

```bash
bun -e 'import {getPluginDocs} from "@akairos/milkdown-article-plugins"; console.log(JSON.stringify(getPluginDocs(), null, 2))'
```

若换机器，先定位这些项目的对应文件；源码或安装包不可访问时，明确这份能力表是上述日期的验证快照，不伪称当前已核验。

刷新时核对实际安装版本、宿主 `.use(...)`、额外 `registerPlugin()` 调用、注册表和解析实现，再核对导出行为。当前默认注册表为 `highlight`、`callout`、`kbd`、`badge`、`article-card`。新语法同时补齐用途、有效枚举、最小例子和导出限制；删除过时说明。

使用小段样稿验证新增或变更语法，至少检查解析后的节点类型与内容；涉及导出行为时再做定向 HTML 导出。更新本文的验证日期和版本，以及入口速查中的相关行。保持同一份 skill 源文件，不在各 Agent 目录复制分叉；维护语法文档本身不需要升级 npm 包或执行真实发布。
